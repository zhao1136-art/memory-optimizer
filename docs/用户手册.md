# MemOptimizer 高效内存优化工具 · 用户手册

> 版本：v1.0 ｜ 适用平台：Windows 7+（x64）｜ 技术栈：纯 C（C11）/ MinGW-w64

---

## 一、软件简介

**MemOptimizer** 是一款纯 C 原生的 Windows 本机内存监控与优化工具。它实时监控系统与全部进程的内存使用，提供**泄漏检测、热点分析、堆碎片统计、运行环境识别、优化建议与安全回收动作**，并通过内置 Web 管理后台与 REST API 提供直观的可视化界面和集成能力。

工具自身轻量低开销：空闲时 CPU 占用约 **0.6%**、内存占用约 **9 MB**（详见《性能测试报告》）。

**核心能力一览**

| 能力 | 说明 |
|---|---|
| 实时监控 | 2 秒级采样全部进程，内存/CPU/句柄/线程全景 |
| 泄漏检测 | 对私有字节/句柄做线性回归趋势取证，输出泄漏速率、拟合度 R²、严重度 |
| 热点分析 | Top-K 进程按私有/工作集/峰值排序，含占比与 CPU |
| 堆碎片统计 | 通过 VirtualQueryEx 统计目标进程已提交区分布，输出碎片指数 |
| 运行环境识别 | 按可执行名识别 Python / JVM / Node.js / PowerShell / .NET / Go / Rust 等 |
| 优化建议 | 规则引擎输出智能回收、大对象、缓存、泄漏四类建议 |
| 安全动作 | 对指定进程执行工作集回收（SetProcessWorkingSetSize） |
| 报告导出 | 一键生成 HTML 报告，支持 JSON/CSV 导出时间序列 |
| 一键优化 | 一键完成：关闭僵尸进程、回收高驻留进程工作集、清理系统缓存 |

## 二、系统要求

- **操作系统**：Windows 7 及以上（64 位；x64 推荐）
- **物理内存**：建议 1 GB 以上
- **运行权限**：
  - 普通用户可监控自身可访问的进程；
  - 查看受保护进程（System、lsass 等）与执行跨进程回收，**建议以管理员身份运行**；
  - 部分功能在权限不足时自动降级并返回中文提示，不影响工具运行。
- **编译环境**（如需自行构建）：MinGW-w64 gcc（C11），无第三方依赖库。

## 三、安装与启动

### 3.1 快速启动（已编译版本）

项目 `bin\memtool.exe` 为已编译可执行文件，无需安装即可使用：

```bat
cd G:\内存优化\ncyh\bin
memtool.exe --serve --config ..\memtool.conf
```

启动后浏览器打开 **http://127.0.0.1:8080** 即可进入 Web 管理后台。

也可使用项目根目录的 `run.bat` 一键启动：

```bat
run.bat
```

### 3.2 自行构建（可选）

项目根目录提供一键构建脚本：

```bat
build.bat
```

构建要求 gcc 位于 `F:\winlibs_mingw-16.1.0posix-14.0.0-ucrt-r3\mingw64\bin`（可在 `build.bat` 中修改路径）。构建产物输出到 `bin\memtool.exe`，并将 `src\web\` 静态资源复制到 `bin\web\`。

## 四、命令行参数

```
memtool [选项]
```

| 参数 | 说明 |
|---|---|
| `--config <path>` | 指定配置文件（默认 `memtool.conf`） |
| `--host <ip>` | 监听地址（默认 127.0.0.1） |
| `--port <port>` | 监听端口（默认 8080） |
| `--interval <ms>` | 采样间隔（默认 2000，最小 200） |
| `--serve` | 启动 Web 服务（默认行为） |
| `--snapshot` | 输出一次系统 + 全部进程 JSON 全景后退出 |
| `--report <fmt>` | fmt 为 `html` / `json` / `csv`，生成报告到 stdout 后退出 |
| `--demo` | 生成一个泄漏进程 + 一个高驻留测试进程并启动服务（用于演示/自测） |
| `--leakchild` | 以泄漏子进程模式运行（内部使用，`--demo` 调用） |
| `--residentchild <MB>` | 以高驻留子进程模式运行（内部使用，`--demo` 调用） |
| `-h` / `--help` | 显示帮助 |

### 常用示例

```bat
:: 启动 Web 服务（默认配置）
memtool.exe --serve --config memtool.conf

:: 指定端口与采样间隔
memtool.exe --serve --port 9090 --interval 1000

:: 单次全景快照（JSON 输出）
memtool.exe --snapshot

:: 生成 HTML 报告到文件
memtool.exe --report html > report.html

:: 生成某进程时间序列 CSV（--pid 指定，默认系统序列）
memtool.exe --report csv --pid 1234 > trend.csv

:: 启动演示进程（泄漏 + 高驻留）并展示
memtool.exe --serve --demo
```

## 五、配置文件 memtool.conf

配置文件采用 `[section] key = value` 的 INI 风格格式，`#` 或 `;` 开头为注释，键值中的前导/尾随空白会自动去除。

### [server] 服务端

| 配置项 | 默认 | 说明 |
|---|---|---|
| `host` | `127.0.0.1` | 监听地址；保持本机则仅允许本地访问 |
| `port` | `8080` | 监听端口 |
| `api_token` | 空 | 远程访问令牌；`allow_remote=1` 时必填，否则远程一律拒绝 |
| `allow_remote` | `0` | 是否允许远程访问；`1` 时远程请求必须携带 `Authorization: Bearer <token>` |
| `cors_origin` | 空 | CORS 白名单（逗号分隔）；留空表示仅本机请求合法 |

### [sampler] 采样器

| 配置项 | 默认 | 说明 |
|---|---|---|
| `interval_ms` | `2000` | 采样间隔（毫秒，最小 200） |
| `window_size` | `600` | 单进程时间序列环形缓冲点数（2~100000） |
| `auto_watch_top` | `40` | 自动纳入趋势监控的 Top N 进程数（当前版本按采样时出现的全部进程建序列，上限 512） |

### [storage] 持久化

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `1` | 是否启用落盘持久化 |
| `data_dir` | `data` | 数据目录（相对运行目录），按日期生成 `mem-YYYYMMDD.jsonl` |
| `retention_hours` | `24` | 保留小时数，超过自动清理旧文件 |

> 示例配置文件见项目根目录 `memtool.conf`。

## 六、Web 管理后台

服务启动后访问 `http://127.0.0.1:8080`，单页后台包含以下区块（每 2 秒自动刷新）：

### 顶栏 · 系统总览
实时显示：可用内存 / 总内存（含可用率）、提交量 / 提交限额、缓存（standby）、系统句柄数、线程数，以及当前采样次数与间隔。

### 泄漏检测
列出被判定为疑似泄漏的进程：类型（私有字节 / 句柄）、泄漏速率（KB/min）、拟合度 R²、历时、CPU、严重度（0~5）。

### 进程列表
全部进程表格，支持：
- **搜索**：按进程名过滤；
- **排序**：按私有内存 / 工作集 / 名称；
- **行内热度条**：可视化私有内存相对大小；
- **点击行**：展开进程详情（私有/工作集/峰值/CPU/线程/句柄/缺页），并绘制私有内存趋势曲线。

### 优化建议
按严重度降序展示建议卡片（回收 / 大对象 / 缓存 / 泄漏），可执行项带「执行」按钮，点击后对目标进程执行工作集回收并弹出结果。

### 运行时分布
按运行时类型（Python / JVM / Node.js / PowerShell / CMD / .NET / Go / Rust / Native / Unknown）统计进程数量。

### 碎片分析
输入 PID 点击「分析」，显示该进程的已提交区数量、已提交字节、最大连续区、碎片指数（接近 0 为整块，越高碎片化越严重）。受保护进程会返回「权限不足」提示。

### 一键优化
顶栏「一键优化」按钮：点击后弹出确认框，确认后执行——
1. **关闭僵尸进程**：长时间低 CPU（<1%）且高驻留（工作集≥64MB）的进程（带系统关键进程保护名单，不会误杀 System/svchost/explorer 等）；
2. **回收工作集**：对高驻留进程执行 `SetProcessWorkingSetSize` 修剪，释放物理内存；
3. **清理系统缓存**：清空 standby 缓存（需管理员权限，失败不影响前两步）。

执行完成后弹出结果汇总（回收数量与释放量、关闭的僵尸进程、缓存清理状态），界面自动刷新。

### 生成报告
顶栏「生成报告」按钮在新窗口打开 HTML 版完整报告（含系统总览、热点、泄漏、建议）。

## 七、功能详解与判定口径

### 7.1 实时监控
采样线程按 `interval_ms` 调用系统 API 获取全部进程与系统内存数据（Toolhelp 枚举 + PSAPI + GlobalMemoryStatusEx + GetPerformanceInfo），写入定长环形缓冲，工具自身内存开销恒定、有界。

### 7.2 泄漏检测（趋势取证）
对每个被监控进程在时间窗口内对 `private_bytes`（或句柄数）做**最小二乘线性回归**，判定为泄漏需同时满足：
- 时间跨度 ≥ 10 秒；
- 相对起点正增长；
- 拟合度 R² ≥ 0.45（私有字节）或 0.5（句柄）；
- 增长速率 ≥ 8 KB/min（私有字节）或 6 个/分（句柄）。

严重度按速率分级：>5 MB/min → 5；>1 MB/min → 4；>0.25 MB/min → 3；>0.0625 MB/min → 2；其余 → 1。

> **说明**：进程级工具无法定位到具体源码分配点，本工具定位为「进程级定位 + 趋势取证」（增长率、R²、时长、句柄异常），已作为设计假设明确。

### 7.3 热点分析
按私有字节 / 工作集 / 峰值对进程排序，输出 Top-K 及其相对全部进程私有内存的占比（share）。

### 7.4 堆碎片统计
对目标进程 `OpenProcess(PROCESS_QUERY_INFORMATION | PROCESS_VM_READ)` 后以 `VirtualQueryEx` 遍历虚拟地址空间，统计已提交（COMMIT）区、保留（RESERVE）区，碎片指数 = `1 - 最大连续已提交区 / 总已提交字节`。
受保护进程或无权限时返回「权限不足」并优雅降级，不崩溃。

### 7.5 运行环境识别
按进程可执行文件名匹配：`python` → Python；`java/javaw/jvm/jdk/jre` → JVM；`node/npm/pnpm/yarn` → Node.js；`powershell` → PowerShell；`cmd` → CMD；`dotnet/csc/msbuild` → .NET；`go` → Go；`cargo/rustc` → Rust；其余原生二进制 → Native。

### 7.6 优化建议规则
| 类型 | 触发条件 | 动作 |
|---|---|---|
| 智能回收 | 工作集/私有字节 ≥ 3 且工作集 > 256 MB | 可执行 `reclaim`（修剪工作集到最小） |
| 大对象 | 私有字节 > 1 GB 且占全部私有内存 > 20% | 建议优化分配策略（不可自动执行） |
| 缓存 | 可用内存 < 15% 且缓存占比高 | 系统级提示（不可自动执行） |
| 泄漏 | 命中泄漏检测候选 | 建议检查对象生命周期（不可自动执行） |

### 7.7 一键优化
对系统一键执行三件事：关闭僵尸进程、回收高驻留进程工作集、清理系统 standby 缓存。僵尸进程判定阈值：近窗 CPU < 1% 且工作集 ≥ 64MB；受保护名单（System、smss、csrss、winlogon、services、lsass、svchost、dwm、explorer、memtool 自身等）与 PID≤50 的进程一律不处理。回收动作为修剪工作集到最小允许值（进程继续运行，不中断）。清理缓存通过 `NtSetSystemInformation` 清 standby 列表，需要管理员权限，失败仅提示不影响其余动作。

## 八、安全说明

- **默认本机模式**：仅允许 `127.0.0.1` / `::1` 等本机地址访问，不暴露到局域网。
- **远程访问**：需在配置中设置 `allow_remote=1` **并配置 `api_token`**，远程请求必须携带 `Authorization: Bearer <token>`，否则返回 401。
- **CORS 白名单**：配置 `cors_origin` 后，非白名单 Origin 的浏览器请求被拒绝（返回 403），不使用通配符 `*`。
- **路径安全**：静态资源与报告路径做规范化校验，拒绝 `..`、绝对 URL 等目录穿越/注入。
- **回收动作**：仅支持 `reclaim` 一种安全动作，需相应权限（同用户或管理员），失败返回明确错误，不影响工具运行。

## 九、数据持久化

启用存储后，服务每 30 秒把一次系统摘要（时间戳、采样数、可用内存、提交、缓存）追加写入 `data_dir\mem-YYYYMMDD.jsonl`（JSONL 格式，每行一条 JSON）。超过 `retention_hours` 的旧文件由看门狗自动清理。

## 十、常见问题

| 问题 | 处理 |
|---|---|
| 启动后网页打不开 | 确认服务是否正在运行；默认端口 8080 是否被占用（可换 `--port`）；确认浏览器访问 `127.0.0.1` 而非远程 IP |
| 碎片/进程详情返回「权限不足」 | 目标进程受保护或属其他用户，请以**管理员身份**运行本工具 |
| 泄漏检测无结果 | 泄漏判定需要至少约 10 秒以上、增长显著且线性拟合较好；刚启动采样数据不足时不会给出结果，请耐心等待若干采样周期 |
| `apply` 回收失败 | 需要 `PROCESS_SET_QUOTA` 权限，同用户进程或管理员可执行；系统关键进程可能被系统保护 |
| 数据文件在哪里 | 默认 `data\mem-YYYYMMDD.jsonl`，可用文本工具查看 |
